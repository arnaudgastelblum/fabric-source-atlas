# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository. Owner-specific rules, if any, are in `CLAUDE.local.md` (ignored by git).

## What this is

**Fabric Source Atlas**: PowerShell 7 tooling that documents what the Power BI / Fabric semantic models of a tenant read: it exports model definitions (TMDL) and turns them into an Excel inventory of source objects (SQL tables / views / procedures, files, other models) plus one query file per table and an offline web page. `README.md` is the user-facing description and FAQ. Everything in the repository (scripts, comments, output, tests, docs) is in English. The repository is public: no company, workspace or server names anywhere in it, synthetic fixtures only.

Windows only, PowerShell 7.2 or later (each script checks `$IsWindows`; the console block needs `$PSStyle`), public Microsoft cloud only (`api.fabric.microsoft.com`). The scripts are saved as UTF-8 **with BOM**, so that Windows PowerShell 5.1 reads the non-ASCII logo and reaches `#Requires` instead of failing with a parse error: keep the BOM when editing.

Three scripts at the repository root, everything they produce under `data\` next to the scripts (default paths are `Join-Path $PSScriptRoot 'data\…'`; `data\` is git-ignored as a whole):

| Script | Role | Talks to Fabric? |
|---|---|---|
| `Extract-SemanticModels.ps1` | TMDL export of workspaces into `data\export\`; `-ListWorkspaces` / `-ListModels` only list | **yes, read-only** (the only one) |
| `Parse-SemanticModels.ps1` | offline analysis of `data\export\` into `data\sources\`: `model_sources.xlsx` (sheets Sources / Models / Schemas), `model_sources.csv`, `model_sources.html`, one `.pq` / `.dax` / `.sql` per table, one `.sql` per model | no |
| `Extract-And-Parse-SemanticModels.ps1` | runs the two above; no network code of its own | via Extract |

Shared options, combinable: `-Workspace` or `-AllWorkspaces` (exactly one, for Extract and the launcher; Parse defaults to all), `-Exclude` (workspace patterns / ids), `-Model`, `-NewOnly`; `-TenantId` (Extract and the launcher, passed to `az --tenant`). Each script shows its help (logo, one-line purpose, then `$usage`: an ordered table of example arguments → what they do, covering every parameter, printed by `Write-UiHelp`) on `/?`, `-h` / `-Help`, `--help`, `help`, and — for Extract and the launcher — when called without argument; comment-based help is reduced to a synopsis.

Renaming a script means updating the launcher (it calls its two companions by name), the messages of Parse (error text, "Generated by" line), the three test harnesses, `README.md` and this file.

## Rules for changes

- **Never run Extract or the launcher against a real tenant from an AI session.** Validate against the fake API in `tests\`. Parse is offline.
- **The exporter must stay read-only towards Fabric.** All HTTP goes through `Invoke-FabricRequest`, whose allow-list accepts only `GET /v1/workspaces` (with or without a query such as `?roles=`), `GET /v1/workspaces/{id}/semanticModels`, `GET /v1/operations/{id}[/result]` and the body-less `POST …/getDefinition?format=TMDL`. Do not add a second HTTP call site, do not widen the allow-list, and re-run `tests\Test-Extract.ps1` after any change to that script. The launcher must keep containing no network code of its own.
- **The access token is never written**: not to the console, verbose / debug streams, files or exception messages. az's stdout is parsed, never shown; its stderr and Fabric's error texts go through `Hide-Secret`; `Invoke-WebRequest` runs with `Debug = $false`.
- **`data\` holds the user's confidential data** (server names, M and SQL code, lineage): never commit it, never use it as a fixture.
- When a change touches the safety properties above, say explicitly what was and was not re-audited.

## Commands

```powershell
# tests — all offline, each prints "ALL … PASSED" and exits non-zero on failure
pwsh -NoProfile -File .\tests\Test-Extract.ps1      # exporter + launcher against a fake Fabric API on localhost, fake az (42 "RUN n" scenarios, ~10 s)
pwsh -NoProfile -File .\tests\Test-Parse.ps1        # TMDL / M analysis on synthetic fixtures, workbook, page, folder guards, tr-TR / fi-FI runs
pwsh -NoProfile -File .\tests\Test-SqlParsers.ps1   # each SQL query analysed by BOTH SQL analysers and compared with an expectation (~10 s)

# Parse on an export (offline; a filtered run keeps the other models' rows)
.\Parse-SemanticModels.ps1 [-Workspace '<folder name>'] [-Exclude '<folder name>'] [-Model '<pattern>'] [-NewOnly] [-QueryFilesOnly] [-NoTSqlParser] [-PassThru]

# syntax check (no linter is configured; PSScriptAnalyzer is not installed)
pwsh -NoProfile -Command '$e=$null;$t=$null;[void][System.Management.Automation.Language.Parser]::ParseFile((Resolve-Path .\Parse-SemanticModels.ps1),[ref]$t,[ref]$e);"parse errors: $($e.Count)";$e'
```

There is no per-test selector: each harness is one script. To work on a single case, add a query to the `$tsql` / `$other` / `$embedded` tables of `Test-SqlParsers.ps1` (expected objects are written `[server:][database:]schema.object`, relative to the connection `srv` / `db`), or a `Put 'tables\X.tmdl'` fixture plus an `Assert` in `Test-Parse.ps1`. Run harnesses in a child `pwsh` with a timeout when a change could loop — a runaway recursion once blocked a whole session. Fixture TMDL must indent every line of an expression (continuation lines of multi-line strings included), as Fabric does, or the expression is cut at the first newline.

## Architecture

The scripts are deliberately separated so that **all code that talks to Fabric sits in one audited file**:

- **Extract** — token from `az account get-access-token --output json` (`Get-FabricToken`): expiry read from `expires_on`, else the JWT `exp`, else `expiresOn` (local time); refreshed 5 minutes before expiry; an HTTP 401 refreshes it once and retries the request once. az failures are told apart (`Get-AzFailureMessage`: not installed, not logged in, MFA / conditional access, no subscription, other AADSTS) with the command to run. The JWT payload is decoded locally to print "Signed in as …, tenant …". Then list workspaces / models, `getDefinition` per model (long-running operation: poll `/operations/{id}`, then `/result`), decode the base64 parts into `<OutputPath>\<Workspace>\<Model>.SemanticModel\` (PBIP layout) and write `_export_report.csv` (merged by ModelId with the previous report on a filtered run). Three parameter sets: `Export` (default), `ListWorkspaces`, `ListModels`; the list sets return objects, skip every output-folder rule and return before any `getDefinition`.
  - Workspaces: `-AllWorkspaces` drops `type` `Personal`. Viewer-only workspaces of `-AllWorkspaces` are filtered up front with `GET /v1/workspaces?roles=Admin,Member,Contributor` (never a workspace named with `-Workspace`, which is always tried); if that request fails or comes back empty while workspaces are visible, the fallback is the first `getDefinition` of a workspace failing with HTTP 403 / `InsufficientPrivileges` (left out, counted in the summary; naming one with `-Workspace` raises a clear error). A workspace whose model listing fails gives a Failed row with an empty ModelId and `Folder` = workspace folder, and the run continues.
  - Resilience: 429 honours `Retry-After` (seconds or HTTP date) up to 600 s, 20 minutes in total per request, 5xx and transport errors (`Test-TransportError`) are retried with backoff; waits show a countdown on the status line (`Wait-FabricDelay`). Guard refusals throw `[Security.SecurityException]`, which always aborts the whole run.
  - Folder names (`Get-FolderNames`, `ConvertTo-FolderName`): sanitised, cut at 80 characters plus ` (id8)`, collisions suffixed deterministically in ordinal id order over all visible workspaces / all models of a workspace. `-NewOnly` keeps a model (`AlreadyExported`) only when the previous report has the same ModelId with the same folder and `definition\model.tmdl` exists.
  - Guards, each added after an audit finding: printable-ASCII + ordinal host check, GUID validation of every id returned by the API and of `-TenantId`, pagination loop guard, any listing status other than 200 is an error, allow-list of part file extensions (a hostile response can never plant a `.ps1` / `.cmd`), part paths (no `..`, device names, trailing dot/space), output folder rules — plain drive-letter path, not under a OneLake File Explorer folder (checked first: local writes there sync back to Fabric), no symlink / junction in the ancestry, other reparse points refused except under `$env:OneDrive` / `OneDriveCommercial` / `OneDriveConsumer` (files-on-demand folders; a warning says the exports will sync), scripts not inside it, and an ownership marker `.semantic-model-tools` (new / empty / marked folder, or `-AdoptOutputFolder`). Inside a git repository the script warns, except under `data\` of its own repository. A model's previous export is deleted only after its new definition was fully downloaded and validated; so is a stale folder that the previous report gave the same ModelId under another name (rename, cut long name), through the same guards.
- **Parse** — offline pipeline, run under the invariant culture (the user's culture is restored in `finally` and for the summary):
  1. **TMDL reading**: line / indent based. An expression is on the declaring line, in a ```` ``` ```` fence, or in the following lines indented deeper; it is de-indented by common prefix. All tables are read first (two passes) because a table's query may reference another table. `.SemanticModel` folders without TMDL (`model.bim`) are counted and reported, not read. `dataSources.tmdl` gives Server / Database to legacy `query` partitions. Model folder names are assigned over the whole export before filtering, so a filtered run uses the same folders as a full one.
  2. **M analysis**: `Get-MMasks` returns `Clean` (comments blanked) and `Mask` (comments *and* string contents blanked) of identical length, so structure is found on the mask and values read from the clean text at the same offsets. `Get-MSources` walks connector calls and `{[…]}[Data]` navigation steps in document order; each let step remembers the connection it holds, so a navigation or `Value.NativeQuery` is attributed to the connection it targets, not to the last one opened. `Resolve-MText` evaluates text expressions (literals, `&`, let steps, model parameters, `Text.Trim`); what it cannot evaluate becomes a placeholder — scalar `{x}` for one value (a date, a non-text parameter), opaque `{?x}` for anything that may hide SQL structure — and nothing built on an opaque placeholder is ever reported as certain. `Get-QuerySources` follows references to shared expressions and to other tables transitively; identifiers inside field-access brackets, record field *names*, M keywords, type names after `type` / `as`, function parameters and differently-cased names are not references, and a let step hides a model query of the same name. Standard-library functions are allowed one by one (`$script:StdFunctions`), never by namespace; `Expression.Evaluate` gives a flagged `{dynamic M code}` row.
  3. **SQL analysis**: Microsoft's ScriptDom T-SQL parser when its DLL is found (SSMS / DacFx / SqlServer module in any `PSModulePath` entry or the real Documents folder; loaded only with a valid Microsoft Authenticode signature, from a file held open without write sharing; syntax tree walked generically by reflection, CTE names and aliases scoped per statement, `CONTAINSTABLE` / `CHANGETABLE` / constant `OPENQUERY` / `EXEC('…')` read, any unknown table-source node marks the result incomplete, and so does a procedure call not starting with `EXEC`), otherwise — or when the text is not valid T-SQL — the built-in lexer + scanner (`Get-TokenSqlObjects`). `#temp` tables, table variables, CTE names, aliases and `dual` are never objects. `[Query]` of `AnalysisServices.*` is DAX / MDX: one flagged "DAX/MDX query" row, never sent to the SQL analysers. Which analyser read a query is written in the `-- Analysed by :` header of the table's `sql\<Table>.sql` file (not in the inventory); `NeedsReview` must stay truthful: set it whenever the tool is not certain (opaque placeholder, incomplete parse, unknown connector), and a row merge never clears it. Known connectors are declared in `$script:Connectors`; an unknown `X.Y(` call is reported as "Source call only, to review".
  4. **Rows**: one row per (model, table, source object). When a SQL object (`$script:SqlObjectTypes`) is written `db.schema.object` or `server.db.schema.object`, the prefix moves to the `Database` / `Server` columns (a prefix wins over the connection's database) so that `Object` always reads `schema.object` (`Split-SqlName` / `Format-SqlName`). Rows are merged per (source, server, database, object) with the paths joined in `Via`. Columns: Workspace, SemanticModel, Table, SourceType, Server, Database, Object, ObjectType, Mode, Via, Parameters, NeedsReview, QueryFile, SqlFile (the last two are paths relative to `-OutputPath`). `Hide-Secret` masks passwords, keys and secret URL parameters (`***`) in every written file and column.
  5. **Output**: `model_sources.csv` (also the store that lets a filtered `-Workspace` / `-Exclude` / `-Model` / `-NewOnly` run keep the other models' rows) and `model_sources.xlsx`, written by hand as a zip of OpenXML parts with text-only cells (no module, no Excel needed; at most 65,000 hyperlinks per sheet): sheet `Sources` (rows above, QueryFile / SqlFile as relative hyperlinks), `Models` (one row per model: counts plus the distinct servers / databases and schemas it reads) and `Schemas` (one row per model × server × database × schema). A DAX calculated table or a table generated in M gets one row without object; the sources of the base table it reads are documented on that base table only.
  6. **Web page**: `model_sources.html` ("Source Atlas"), written by `Export-HtmlReport` from the same final rows as the workbook. The page is the single-page app held in the here-string `$script:HtmlTemplate` (HTML / CSS / vanilla JS, no external resource, no network API, CSP `default-src 'none'`): overview, search, impact view, model view with the query code, lineage in two styles (cards, or Sankey-like flow coloured by schema; Ctrl + wheel zooms), to-review list. The data — rows plus the text of their `QueryFile` / `SqlFile` (kept in memory for files written in this run, read back from `-OutputPath` otherwise) — is streamed as JSON → gzip → base64 in place of the template line `<!--MODEL_SOURCES_DATA-->`, as `<script id="model-sources-data" type="application/octet-stream" data-encoding="gzip-base64">`; the page decodes it with `DecompressionStream` and inserts data only as text (`textContent` / `createElement`, never `innerHTML`); route types come from a fixed list. Keep those properties when editing the template. A failure of the page step is a warning: the CSV and workbook are kept. `-QueryFilesOnly` does not rewrite the page (like the workbook).
- **Launcher** — runs the two above in order, passing workspace *folder* names taken from the export results (they differ from display names containing characters invalid in file names; a row without ModelId names the workspace folder itself). It defines `$SemanticModelToolsRun` (step counter, start time), which the two scripts find through PowerShell's scope chain: they then print `[1/2]` / `[2/2]` headings, and only the analysis prints the final summary.
- **Console display** — a block between the markers `console display (begin)` / `(end)`, **identical in the three scripts** (Test-Extract RUN 24 checks it: edit one copy, then copy it to the other two). Colours, Unicode marks (`✓ ! ✗`, braille spinner) and OSC 8 clickable paths only on an interactive console in Windows Terminal / VS Code; elsewhere ASCII (`[OK] [!!] [XX]`), and plain text when the output is redirected or `NO_COLOR` is set. The opening title carries the author's credit (`by Arnaud GASTELBLUM · lazysnail.net`, a link) and, with colours and Unicode in a window at least 70 columns wide, the Lazy Snail logo: 16 × 11 braille characters in `$script:UiLogo`, with one soft 24-bit colour per character (a letter per character, palette of six). The status line (spinner, bar, counter, current item) is drawn every 100 ms by a background runspace through `$Host.UI.Write`, so it moves while a request or an analysis blocks; it is off under `-Verbose` / `-Debug`. Every long phase sets it (`Set-UiStatus`), so users always see where the run is. While it runs, every console write must go through `Write-UiLine` / `Write-UiWarning` (they take its lock and clear the line); `Stop-UiStatus` sits in a `try/finally` around the work, so Ctrl+C cannot leave it running. A `trap` turns an error into a short red message and exit code 1 only when a person typed the command (`CommandOrigin` `Runspace`); a calling script (the launcher, the test harnesses) still gets the exception.

## PowerShell pitfalls that already bit this codebase

- Variable names are case-insensitive: a `[string]$M` parameter silently turns every `foreach ($m in $rx.Matches(…))` item into a string.
- `return , $list` combined with `@(…)` at the call site hands back the list as ONE item (an empty list stringifies to `''`) — this caused unbounded recursion. Return `$list.ToArray()` and wrap calls in `@()`; return a result object when "empty" and "failed" must differ.
- `[math]::Min(<int>, <double>)` binds the Int32 overload and overflows: cast to `[double]`.
- `-eq` / `-ne` / `-match` are case-insensitive and culture-aware (they ignore zero-width characters): security-relevant comparisons use `[string]::Equals(…, Ordinal)`, `-ceq`, `-cmatch`, and `\A…\z` rather than `^…$`. `[ordered]@{}` / hashtable keys are case-insensitive too: M is case-sensitive, so query names are also kept in an ordinal `HashSet`.
- `(?i:…)` in .NET regexes follows the current culture (Turkish: `(?i:TRIM)` does not match `trim`): Parse runs under the invariant culture. PowerShell's regex cache ignores culture, so culture tests must run in a new `pwsh` process.
- `Invoke-WebRequest -TimeoutSec` rejects values above ~24 days, and in debug mode prints request headers including the bearer token (hence `Debug = $false`). A stub of the cmdlet does not catch either: the export harness wraps the *real* cmdlet against a local `HttpListener`.
- `Get-AuthenticodeSignature -Content` only understands scripts, not DLLs (it reports `NotSigned`): check a DLL by path while holding it open.
- `Set-StrictMode -Version Latest` is on: property access on `$null` and out-of-range indexes throw.
- Every .NET method call in a hot loop is slow (5–35 µs each on a machine with an antivirus hooking PowerShell, against ~1 µs for an operator): in character loops use operators, indexing and `-join`.
- `[Array]::Sort(keys, items, comparer)` without `[Array]` / `[IComparer]` casts sorts a copy of `items`: the original order does not change.
- `Remove-Item` on a path that a hook considers protected is blocked without appeal: never build cleanup paths from string fragments that may end in a backslash followed by a dollar sign.
- `Sort-Object` on names is culture-aware: `[TEST] …` sorts before `Other`. Tests compare sorted sets rather than positions.
- A `replace_all` edit of a short repeated token (such as an argument `'' 'n/a' ` in a positional call) can eat characters of neighbouring tokens: check the result with `cat -A`.
- Files read by Windows PowerShell 5.1 without a BOM are decoded as ANSI: keep the scripts in UTF-8 with BOM.
